# رزا

همراه آفلاین مراقبت از پوست، مو، چرخه ماهانه و نوبت‌های آرایشگاه و پزشک.
فارسی، راست‌چین، تقویم شمسی، بدون نیاز به اینترنت.

## ۰) پیش‌نیاز مهم: فونت

قبل از اولین اجرا، سه فایل فونت را در `public/assets/fonts/` قرار بده:

```
Vazirmatn-Regular.woff2
Vazirmatn-Bold.woff2
Vazirmatn-ExtraBold.woff2
```

جزئیات در `public/assets/fonts/README.md`. بدون این فایل‌ها اپ کار می‌کند
ولی با فونت پیش‌فرض سیستم (دقیقاً مشکل نسخه ۱).

## ۱) اجرا

```bash
npm ci
npm run dev
npm run lint     # بررسی تایپ‌ها
```

## ۲) ساخت اندروید

```bash
npm ci
npm run build
npx cap add android
npm run android:build
```

## معماری

### قواعد غیرقابل مذاکره

1. **هیچ عدد جعلی.** اگر داده کافی نیست، سرویس‌ها `null` برمی‌گردانند و UI
   از `EmptyState` استفاده می‌کند (پیشرفت تا داده کافی، نه عدد حدسی).
2. **تاریخ محلی.** هرگز `toISOString()` برای ساختن تاریخ روز استفاده نکن.
   فقط `toIsoDate()` و `addDays()` و `getDaysDifference()` از `services/jalali.ts`.
3. **داده فقط از `services/db.ts`.** کامپوننت‌ها مستقیم به localStorage یا
   IndexedDB دست نمی‌زنند.
4. **ترکیبات با شناسه.** هرگز مقایسه متنی نام ترکیب.
5. **چرخه اختیاری است.** هر محتوای چرخه‌ای باید پشت `cycleVisible` باشد.

### لایه‌ها

```
config/appConfig.ts          فیچرفلگ‌ها، API_BASE_URL، SHOP_BASE_URL
services/storage/            IndexedDB (kv + blobs) با کش همگام
services/db.ts               تنها درگاه داده + مایگریشن نسخه ۱
services/jalali.ts           تقویم شمسی و ریاضی تاریخ محلی
services/cycle/              موتور چرخه، پیش‌بینی تطبیقی، الگوی شخصی
services/safety.ts           بارداری، شیردهی، دارو، تداخل قفسه
services/providers/          قواعد خدمات، نوبت‌دهی، دایرکتوری (فاز بعد)
services/shop/               کاتالوگ فروشگاه (فاز بعد)
services/telemetry.ts        صف رویدادهای ارجاع (مدل درآمدزایی)
```

### فازهای بعدی

همه زیرساخت آماده است. برای فعال کردن هر فاز، کد UI عوض نمی‌شود:

| فاز | کاری که باید بکنی |
| --- | --- |
| دایرکتوری آرایشگاه طرف قرارداد | `API_BASE_URL` را پر کن و `providerDirectory` را true |
| رزرو نوبت از داخل اپ | `onlineBooking` را true کن (`bookingMode` در مدل هست) |
| فروشگاه وب | `SHOP_BASE_URL` را پر کن؛ دکمه‌های خرید خودبه‌خود فعال می‌شوند |
| سنک ابری | `cloudSync` را true کن؛ هر رکورد `SyncMeta` دارد |

### مدل درآمدزایی

برای تسویه حساب با آرایشگاه و پزشک، لازم است اثبات شود «این نوبت از
طریق رزا بوده». `services/telemetry.ts` این را محلی صف می‌کند:
`provider_called`، `booking_created`، `booking_completed`، `product_purchase_clicked`.

دو قاعده:
- فقط رویدادهای مربوط به `partnerId` یا `catalogId` صف می‌شوند. رفتار کاربر
  با داده خودش ردگیری نمی‌شود.
- هیچ داده سلامتی، چرخه، عکس یا یادداشت در رویداد قرار نمی‌گیرد.

مراکز طرف قرارداد در UI برچسب «معرفی رزا» می‌خورند (`isSponsored`).
این شفافیت اجباری است؛ قاطی شدن دفترچه شخصی کاربر با تبلیغ، اعتماد را می‌سوزاند.

### حریم خصوصی

- تمام داده روی دستگاه است. تنها درخواست خارجی، آب‌وهوا (open-meteo) است
  که فقط نام شهر می‌فرستد و قابل خاموش کردن است.
- قفل PIN با SHA-256 و نمک تصادفی. خود PIN ذخیره نمی‌شود.
- متن خنطی اعلان‌ها پیش‌فرض روشن است.
- گزینه پاک کردن کامل داده‌ها در منو.

### مرز پزشکی

رزا تشخیص نمی‌دهد و دارو تجویز نمی‌کند. هیچ عددی به عنوان «سطح هورمون
شما» نمایش داده نمی‌شود. متن ثابت در `MEDICAL_DISCLAIMER_FA`.
